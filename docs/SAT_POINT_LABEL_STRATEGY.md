# SegmentAnyTree point-label strategy for tree groups

Status: design and input contract, 22 September 2026. **No Auckland fine-tuning PLY has been certified or used for training.** This note distinguishes the reference-set task from the model-input task.

## Two different uses of the labels

Pretrained SegmentAnyTree inference takes an unlabelled LAZ/point cloud. The existing `tree_group` polygons are not an inference input, and the model may predict several instances inside one group. The classical CHM pipeline likewise predicts from its raster inputs. The reference polygons are used later for assessment.

Supervised local fine-tuning is different. The pinned SegmentAnyTree dataset reader expects one PLY vertex per LiDAR point with `x,y,z,semantic_seg,treeID` (the upstream conversion example also writes `intensity`). Raw `semantic_seg` is 0 for unknown, 1 for non-tree, and 2 for tree. Raw `treeID` is -1 for non-tree/unknown and a distinct non-negative integer for each verified tree. The reader subtracts 1 from the semantic class and adds 1 to the instance ID. The PLY must retain a documented local coordinate origin so its points can be checked against the Auckland site extent. The upstream loader assigns files to train/validation/test from the filename suffix, so filenames and dataset configuration need an explicit split audit.

Neither an individual 2D crown nor a `tree_group` polygon is a checked 3D point-instance label. A polygon cannot safely label the entire vertical point column: ground, structures, understory and neighbouring crowns may occur at the same XY position. The local 2D refinement program supplies candidate boundaries and review regions only; it produces no `semantic_seg` or `treeID` values.

The 492 original polygons were accepted by the supervisor as annotation *work*, with groups reported separately; this was not a requirement that fine-tuning must contain 500 independent point-labelled trees. Even treating every accepted single crown as a potential training seed yields only 74 train-site candidates before 3D verification. Validation and test crowns cannot be moved into training to increase that count. If 500 independent single-tree reference objects were interpreted literally, the accepted 234 would be 266 short, but that interpretation is not the supervisor's stated freeze decision rule; a small targeted top-up remains undecided.

## Practical route to a model-ready input

1. **Keep the pretrained model experiment independent of annotation.** Run inference and density thinning on the existing LAZ as planned. Treat predictions as annotation *candidates* on training sites only; never call them reference truth.
2. **Select complete, small training point-cloud regions.** Start from the 74 accepted train-site single crowns and the 87 train-site groups. Prioritise groups with visible individual boundaries and weakly represented strata, including conifers and small/subcanopy trees. A region is useful only if its tree and background points can be reviewed together, including crown overlaps and plot edges. Record the input LAZ hash, site, spatial bounds, coordinate origin, imagery/CHM used, and reviewer.
3. **Annotate and check points in 3D.** Use the 2D crowns, CHM peaks and optionally pretrained predictions as visual guides. Assign a distinct `treeID` to each defensibly separable tree, with raw semantic class 2. Assign class 1 and ID -1 only to checked non-tree points. Review ambiguous boundary and unresolvable group points explicitly; do not turn a whole group into one tree or into negative background. The reviewer should inspect vertical slices and adjoining trees rather than accepting a 2D extrusion.
4. **Export only verified complete supervised regions to the upstream PLY schema.** For the current unmodified PointGroup losses, the conservative choice is to omit unresolved points/regions from fine-tuning samples, or to create complete smaller crops that have no unresolved group interior. Although raw semantic 0 and ID -1 look like ignore labels in part of the code, the proposal score and mask losses have not been validated to ignore all such points. Mixing partly labelled groups into the stock trainer requires a separate loss-path test and possibly code changes. Never use raw semantic 2 with ID -1 for an unresolved group: the loader and instance-target builder can treat its points as one inconsistent instance.
5. **Validate before launching training.** Save a genuine, reviewer-attributed QA record for each PLY, including `point_labels_manually_checked: true`, `reviewer`, `site_id`, `ply_sha256`, and `coordinate_origin_xyz_m`. Run `scripts/21_validate_point_labels.py --ply INPUT.ply --qa-record QA.json --output REPORT.json`. The validator checks the upstream format, raw labels, site bounds, train split, hash and QA declaration. It cannot establish biological correctness. A one-batch forward/loss/backward smoke test on the VM is still needed before any fine-tuning result is reported.
6. **Preserve provenance and keep evaluation separate.** Record whether an instance was manually traced or model-assisted, the source polygon ID, and any excluded ambiguous points. Fine-tuning may use manually verified training-site instances only. A model-assisted training label does not become independent reference truth. Freeze the reference set after the S016/S020 blind comparison and adjudication; assess the held-out sites once under the fixed scoring rules.

## What the current files actually provide

`scripts/26_refine_tree_groups.py` and `scripts/27_validate_group_refinement.py` make and geometrically check 2D revisions. `scripts/29_prepare_group_workflow.py` generates the accepted reference layers and train-only point-annotation *QA regions*. `docs/group_refinement_2026-09-18/workflow_accepted234/summary.json` explicitly says `point_labels_created: false`. `scripts/21_validate_point_labels.py` can validate a reviewed PLY but does not create it. The upstream `sample_data_conversion.py` shows the required PLY fields and transforms an **already point-labelled** LAS file; it is not a converter from crown polygons to ground-truth instance labels.

The local SegmentAnyTree paper (Wielgosz et al., 2024, *Remote Sensing of Environment*, DOI 10.1016/j.rse.2024.114367) reports manually annotated unique tree identifiers in its source point clouds and point-wise instance matching. Dalponte and Coomes (2016, DOI 10.1111/2041-210X.12575) supply a useful seed/region-growing approach to proposing individual crown boundaries, not a substitute for independent labels. This project can use model or CHM proposals to speed **training-site annotation**, followed by manual 3D correction. No cited method establishes that an unresolved group polygon can be automatically converted into several true tree instances.

## Decision and remaining gap

The 2D group treatment is defensible for the current reference evaluation and is deliberately incomplete for supervised fine-tuning. A stock SegmentAnyTree fine-tune remains blocked until checked training-site point instances exist. Creating a formatting script alone would not remove that dependency. The next concrete deliverable is a small, completely reviewed training PLY and a successful one-batch loss-path test; only then should the number of reliable training trees, class balance, and the value of a full fine-tune be reassessed. The reference-set top-up decision is a separate question about stratified evaluation precision, to be made with the supervisor after the blind labels return.
